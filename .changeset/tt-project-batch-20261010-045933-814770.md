`tt-project`:

- review-area cap uses the main-file fallback only once the review's own lineage has 2 failed reviews; before that a review on the same main file joins only with overlapping hunks or functions; review-area overlap names the innermost function around each hunk, read from the base file, so edits to different methods of one class no longer overlap through git's class-level hunk header; hunk ranges compare half-open
- tt-box-clean-probe, a model-free read-only start_when/end_when probe for 'box clean for N hours' (uptime + broker recent jobs; exit 0 clean, 1 not yet, 255 unknown; uptime only without a broker); tt-box-clean-probe dates each job by when it went wrong (finished, else started, else queued; a running job or a hold still on counts as now) and reads broker times as naive local, as the broker writes them; tt-box-clean-probe counts the broker's live 'device HELD (degraded)' row as a hold on now, and tenant jobs left '[MCP killed ...]' by a chip drop as incidents
- shared machines get one recovery owner and a change ledger every co-tenant sees
- the daemon holds an uncommitted harness/schedules.json edit while a harness task runs; applies it once committed or once no harness task runs
- ask gate refuses an access ask about a host the machines list, a resource memory entry or the ssh config knows when it lists no route tried with its result; a notify that hands an override or recovery the project made back as a question (keep or remove?) is refused
- a batch that died mid-push counts its unreadable-remote window from the first recovery look (kept in the marker as pushing.first_checked), not from the push, so a long outage no longer declares it died on the first look
- a heal check that holds its self-fix task owns the failure: its schedule queues no second schedule_fix task and raises no schedule:<name> alert beside heal:<name>
