tt-project 0.2.997: every ssh a project starts shares one connection per host. Probes, heal checks, checks-host runs, the daemon's own ssh calls, and workers' ssh and git over ssh go through the harness's `bin/ssh`, which runs the real ssh with OpenSSH multiplexing (ControlMaster=auto, ControlPersist=600, ServerAliveInterval=15, ServerAliveCountMax=3). An ssh agent that signs each new connection now signs once per host every 10 minutes, not once per command. Sockets live in `~/.tt-project/cm` (mode 700), or in `/tmp/ttp-cm-<uid>` when that path is too long for a socket. The user's ssh folder and config are never read or changed by tt-project, and `-F`, ProxyJump and BatchMode work as before. Calls that set their own sharing (`-S`, `-M`, `-O`, ControlMaster, ControlPath) or forward ports or stdio (`-L -R -D -W -w -N -f`), and verbose calls (`-v`, whose master would keep a captured caller's stderr open), are left as they are. A plain file or symlink left in the socket folder is removed before ssh starts. The wrapper execs the real ssh, so stopping or timing out the caller stops ssh and its remote command; a shared connection that fails before the command starts is left to OpenSSH, which connects directly. `ssh.reuse` off also reaches the daemon's own ssh calls (set in its environment on each config load). `ssh.reuse` (default true) turns it off: `ttp config <project> ssh.reuse false`. A worker's start reads the unlanded branches in one git call, and the tick's worktree sweep runs no git per kept worktree and runs at most every 3 minutes.
