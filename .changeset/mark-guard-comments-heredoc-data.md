The run-mark guard reads a `#` as a comment only where it starts a word, as the shell does, so `rm a#b <record>` is refused instead of passing. A heredoc body that only cat or tee writes to another file (quoted delimiter, nothing piped on, and every other command in the line only prints or reads) is read as data, so a prose line naming the record in it no longer stops a worker; a body run by a shell or interpreter, piped on, or written to the record itself is still refused. Whether a word before the record in a prose clause is a command comes from a PATH lookup again, with a fixed list adding commands a host may lack; a clause whose first word names an installed command is never prose. A prose word that happens to name an installed command (a reader like cat or ls) is refused too: an accepted gap of the PATH lookup, kept rather than patched.

When the guard cannot tell where a comment ends, it refuses a command that names the record instead of guessing: a comment ending in a backslash beside a heredoc (bash ends the comment at its newline, so the next line runs), or a comment in a command that also has a `${...}` expansion (a `#` inside one is no comment). So `: ${x:- #} ; rm <record>` and a comment that ends in a backslash followed by `rm <record>` on the next line are refused.

A comment starts where the shell starts a new word: after an unescaped space, tab, newline, `;`, `&`, `|`, `<`, `>` or `(`, after a backslash-newline that follows one, and after the `)` that closes a subshell, `(( ))` or case pattern. So `(true)# note`, `((1))# note`, a case pattern's `)# note` and a note after a continued line can no longer hide the next line behind the note's quote. After the `)` of a paren that continues a word (`$(...)`, `<(...)`, `a=(...)`) or after an escaped break character (`a\ #b`) the `#` is part of the word. Inside `(( ))` or `$(( ))` a `#` starts no comment, as in bash, so `(( x=1 #')); rm <record>` is refused. The shell-quote walk keeps this rule in one place, and the record guard and the credential watch read it instead of keeping their own copies. Since `f()# note` is a comment in bash but reads as a word here, a `#` right after an unquoted `)` makes the record guard refuse a command that names the record.
