`tt-project`: the "tt models unavailable" alert counts only cheap Claude runs whose route really failed on the chat endpoint (a fault, a cool-down, the auth gate, full slots); a chat-class run kept on Claude by a keep-core rule (a code arm, urgent, protected or untrusted work, the floor) is labelled "kept on core" and raises nothing. A spill health pass where every host fails splits the hosts that failed to connect through the forwarded loopback route (the tunnel event) from the rest, which are a config fault only when at least `CONFIG_FAULT_HOSTS` of them fail and are otherwise each taken out on their own until they pass.
