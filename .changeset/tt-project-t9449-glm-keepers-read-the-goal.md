`tt-project`: on the GLM work route, the design and device keepers read only the task's own goal: the title and the spec above its first `Context:` or `Restrictions:` line (the whole spec without one). Quoted user words, findings and restated rules no longer keep implementation work on Opus. The design keeper keeps optimization, redesign, architecture, design and proposal goals, hard debugging, deadlocks, race conditions and the code arm's judgment patterns; metric words (perf, latency, throughput, root cause, bisect) alone keep nothing. A question or work task titled as a review of another task stays on Opus (`review`). Device resources still keep a task, and so does a goal naming a device action or a job through a device broker.
