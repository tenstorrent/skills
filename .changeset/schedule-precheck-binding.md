`tt-project`: an llm schedule's run keeps the evidence its precheck admitted it on. A precheck that exits nonzero may print one JSON object (at most 4 KB; `snapshot`, `captured_at`, other keys kept) as its last stdout line; it is stored with the task when it is queued and handed to the run as `$TTP_PRECHECK_JSON` and a spec line. A later precheck, a moved latest pointer or a stats re-read never replace it; missing, invalid or oversized output, a failed precheck and a timeout bind `unknown`.
