tt-project 0.2.998: restrictions written in a charter's Brief now bind. The Brief runs from its heading through its own sub-headings up to the coordinator's sections (Goals, Policies, Resources, Responsibilities, a dated added section or the binding Restrictions block) or an explicit end line, and its restriction items carry origin Brief. A `## Restrictions` heading right after a Brief with no sub-headings of its own still ends it. The credential guards treat any `*known_hosts*` file and ssh's client config (`~/.ssh/config`, `~/.ssh/*_config` and their temp and backup copies such as `config.tmp.*`, `config.bak-*`, `config~`) as settings, not credentials: they are not watched and a change to them never fails a run. Private keys (`id_*` without `.pub`, `*.key`, `*.pem`) stay guarded. A watched credential change fails a run only when the run's own transcript names the file or runs a writer for it. A change made by another process on the host is reported as an observation and the run goes on. `ttp new --relayer` turns `coordinator.agent_orders_as_user` on, recorded with its setter, and never overwrites a value already set. Other projects keep the old default. A failed secret fetch is cached for 15 seconds instead of being retried at once, and the `secrets_unmasked` path has a test.
