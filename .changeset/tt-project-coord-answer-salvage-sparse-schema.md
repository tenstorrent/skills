`tt-project`: a coordinator wake (a new or resumed session wake, or a stateless turn) whose budget ended it on its whole final answer is applied instead of lost. A session wake's session resumes, and its next wake is told the answer was applied so it does not resend it. On Claude Code (and chat) the answer is the final `StructuredOutput` call the CLI never ran when `--max-budget-usd` stopped the run; on Codex and Cursor it is a whole JSON final message the runner's budget check cut off before the turn ended. The answer goes through the same action checks as any other, and the turn no longer counts as waste for the runaway guard. Subagent calls, calls that ran or were denied, and other endings are not salvaged. Claude Code's coordinator schema now requires only each object's own fields (`strict_schema(require_all=False)`), so answers leave unused fields out instead of padding every action with about a hundred nulls; Codex keeps the all-required schema its strict mode needs. Under either schema a null is unused and a schedule field is cleared only through `clear_fields`, as before. The coordinator prompt and the provider matrix say so.
