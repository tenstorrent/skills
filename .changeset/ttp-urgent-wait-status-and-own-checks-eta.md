Urgent work and the waits it names. An urgent task asleep on its own hand-off wait reads 'waiting 2h13m' in status, the coordinator digest and the web app (its waiting row says what on), not 'deferred until' or 'no estimate'; an urgent task's own wait that no queue explains raises one must-act item after 15 min. A user order asking for it today or now, given no due, is due by the end of that home-zone day; 'not urgent' never counts and an explicit due wins. An urgent code task hands off for review once its CPU checks pass, with any device, cluster or remote smoke running beside the review. `ttp eta` gives a task waiting on its own `ttp checks` a finish from the wait's start plus the median of recent completed checks runs, keeping 'outside work' for real outside waits. Durations share one format (timefmt.dur).

Follow-ups a done task hands off, of any kind, stay in the coordinator's digest under 'Open follow-ups' for a day until a task takes one up or the coordinator drops it with `ttp task <project> drop-followup <id> "<why>"`. `ttp said --notes` also searches notes from other projects, labelled as data, not the user's words.
