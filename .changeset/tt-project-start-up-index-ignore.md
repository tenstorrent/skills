"tt-project": patch

`tt-project`: workers and coordinator turns no longer walk a project's bulky folders when their CLI starts. Claude Code counts the files under its working directory at start-up (`rg --no-config --files --hidden <cwd>`, on every core), and Cursor's agent walks it too; in a project root with a large `results/` tree, or in the harness folder with its run folders, that took seconds of CPU on many cores per run. The daemon now keeps a marked block in the project root's `.ignore` (read by rg even with `--no-config` and outside git) listing `/tt-project/state/`, `/tt-project/worktrees/`, `/results/`, `/tmp/`, `/runs/` and `/worktrees/`, written at project creation and at each daemon start, so `ttp setup` and `ttp upgrade` bring it to existing projects. Folders are anchored at the root; a search started inside one (a code task's worktree) or given its path, Claude's Glob and git itself are unaffected; a Grep from the root with no path skips them, as the worker prompt now says. A `.ignore` the project tracks in git without the block is left alone; one the daemon creates in a git root goes in the repository's local exclude file, so it shows in no `git status`.
