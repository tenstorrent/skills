`tt-project`: one rule decides which words of a spec are the task's own (`glmwork.own_words`: the title and the goal above the first Context or Restrictions line, without quoted words, untrusted data spans and `>` lines). The optimization keeper (route.protected), the model pick's hard-work check and the GLM work route's design and judgment keepers read it. A spec that quotes a user's routing order, such as one listing optimization among the work that stays on the core model, no longer keeps the run itself off a routed model or the GLM code arm, on projects the GLM work route covers or not. The task's own words still keep it on core. The device keepers read the same goal with quoted words kept, since a quoted command such as `"tt-smi -r 0"` is the task's own instruction; a device word only in a data span or a `>` line keeps nothing. The quote rule (`untrusted.QUOTED`) is shared with the charter guard's ban clauses, so an apostrophe inside a quoted word (user's) no longer lets a ban word leak out of the quote.
