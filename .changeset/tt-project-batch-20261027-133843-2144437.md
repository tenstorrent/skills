`tt-project`:

- the chat bridge maps upstream context-length errors to 'prompt is too long' (Claude Code compacts on it); a chat tier's context_window sets the agent's compaction window; pricing.chat reprices chat runs from their tokens (budget caps read that figure), else their spend is booked as estimated
- three timing-sensitive tests hold under host load (lock waiter syncs on its first busy take, derived pre-stage rerun keeps the product timeout, boot check bounded by CPU time); the derived pre-stage timeout test counts its 6 s cut-off from test_hangs' start (boundedchild on_start), so a loaded host's pytest start-up cannot use it up
- the worker gh guard checks PR bodies written through issue routes (gh issue edit, issues PATCH/POST, GraphQL updateIssue) when the target is a PR or the lookup cannot tell, and gives every /graphql spelling and repositories/<id> path the draft, ready and reviewer decisions of gh pr; the worker gh guard treats GitHub Enterprise's https://<host>/api/graphql as GraphQL (ready, draft-only create, reviewer and PR body checks) and looks PRs named by a full URL up on that URL's host
- the daemon records the harness HEAD and runtime tree it loaded, ttp status shows loaded vs current (stale when they differ), a moved tree restarts the daemon once through the runtime-change restart, and runtimeload decides by the recorded tree, not file times; a start_after keeps not_before in the whole seconds its label holds, so the start-hold pass no longer moves not_before by the label's rounding (fixes a flaky start_after test); a restart on a moved runtime tree also waits while a run still works in the harness checkout (its end restarts) and while ttp upgrade holds the harness-upgrade lock (it restarts the daemon itself)
- a regression test that a fractional start_after keeps not_before equal to its whole-second deferral label
- the push queue reruns a blamed failure's failing tests on the tip up to 3 times (batch.TIP_RERUNS) before sending any entry back; one failing there makes it pre-existing: entry 1 ends tip_failed, a later entry is requeued while the prefix that passed goes, and the marker (pre_existing, checks.tip_reruns) and the coordinator are told
- ttp leftover-procs, a hand-off check that claims a process only by its resolved cwd under the task's own worktree (whole path components), never a bare t<id>
