`tt-project`: GLM runs may pass `ssh` `-o` options that run nothing, and `-F` with a settings file inside their own worktree or run folder that runs no local program, in a single plain call; specs that commit in the harness tree keep their run on the core provider; and the glm_work judge counts a task that bounced to the core provider only for its bounce, while a core retry of GLM's own failed work still counts against GLM.

A GLM run's code hand-off is also sent back when it adds a comment or docstring that names an incident instead of a rule, adds tests with no run line showing them fail on the base commit, or leaves a numbered spec step unnamed in its self_check; GLM's code prompt asks it to list every reader of a field or file it changes.
