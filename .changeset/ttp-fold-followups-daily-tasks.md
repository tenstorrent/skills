`tt-project`: fewer, bigger tasks. A done task's follow-up that names the same branch, the same files or the same task lineage as a queued task of its kind is folded into that task (appended to its spec) instead of being proposed as a new task. Only a queued task that can start now (not deferred, dependencies met) and matches the follow-up's urgency takes it: an urgent or obligation-owning task's next steps fold only into urgent or same-obligation work, else they are queued at once as before, and routine follow-ups never fold into urgent work; a running task never takes one, so a run that already handed off cannot lose it. Upstream notes, deferred, `continue:`/`mechanical:` and post-landing follow-ups, and those of reviews or approvals, never fold; one that matches nothing stays proposed, and each fold is logged and named in the hand-off. `chains.fold_followups` false turns it off. New `tasks.daily_target` (default 0, off): when set, `ttp throughput` and the coordinator's state show the tasks created in the last 24 h against it, with how many were reviews.
