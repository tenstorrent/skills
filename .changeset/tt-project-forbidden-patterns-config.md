Forbidden-data patterns are read only from `memory.forbidden_patterns` (and `memory.forbidden_patterns_file`), never from the charter's wording. An older charter's `Forbidden data` section moves into that setting once, before its first read, so no pattern lapses; a coordinator `charter_update` to that section adds its patterns there. A charter sentence such as "the branch is ready" no longer moves `is` into `worktree.shared_branches`: only names with a `/` or that exist do, and prose words the harness already wrote there are dropped once (a list a user or coordinator set is untouched).
