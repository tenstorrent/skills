`tt-project`: every Claude run (workers, reviewers, coordinator wakes; fresh, resumed or forked; finished, failed or lost) is now booked at what its own API calls cost: each call the run's output names counted once, at the final token counts Claude Code's session log recorded, at list price, with 5-minute and 1-hour cache writes each at their own rate, subagent calls included and other vendors' models (GLM) left out. The run's output.jsonl alone is not enough: Claude Code streams each call's usage as it was when the call started, so its output tokens there are a few percent of the real count and a run booked from them alone came out about 31% low; the session log holds each call's final count. Claude Code's reported total, which in a resumed or forked session is the whole session's running total, is no longer booked; it is kept in the run's note, and still sets the coordinator's per-wake cap. A resumed or forked run that made no call (lost or failed before its first answer) books $0, whatever its result reports. While a run is going, the minute meter reads each session log only from where its last pass ended (from the start again if the log shrank or was replaced), not tens of MB each minute. Each project re-books, once, its Claude runs of the last 7 days at their per-call cost, up or down, with matching task spend and signed ledger rows, so the dollar caps and the daily total count each call once; it runs as a tick step in short slices (about 2 seconds or 200 runs each) that keep their place, and the daemon log says, when it ends, how many runs moved and the dollars before and after.
