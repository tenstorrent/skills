`tt-project`:

- a push batch never counts a tip check skipped on an empty self-diff as a tip pass, and reruns many failing tests on the tip alone before blaming the entry
- landing checks are flagged over 5 min and a slow project gets one priority-1 test speed-up task naming its slowest tests; tt-project tests: the local runner sizes workers to free cores and starts the slowest tests first; slow smoke tests swapped for fast ones in their areas
- a chat pause with no saved endpoint key is checked model-free, so no probe run launches every 15 min only to fail
- detached ttp push waiters take the push lock by priority (urgent or user-ordered first), then age; push.take tolerates no project (test callers)
- test that a changed machine.max_workers is published without a new claim
- abandon cancels the task's daemon review, no review is queued for abandoned work or a cancelled head, and a claim probe that could not reach its host is retried; the checks demand samples are durable-exempt with a reason (the tip already trimmed the prompts and made the machine-workers write durable)
- hold duplicate and superseded tasks at dispatch, stop running tasks once superseded; supersede guard never holds a schedule's recurring runs, and a landing record from before a run began never stops it
- ttp upgrade first refreshes a stable copy older than the newest release on the host; tt-project tests: smoke list covers the stale-stable case file
- one listener per chat id (a lease naming the listener; another relayer is refused or, after the lease lapses, its takings are redelivered to the owner), and relayers wake only for user-facing messages, broadcast alerts batched; the relayer lease is written with durable_write; a reply or ask posted to every chat wakes each relayer at once (never skipped and read past), and listen and connect retry without --holder on an older remote runtime; a lease refusal is not retried
- pathguard: reads the text ssh runs on a host (its remote command, a stdin file, pipe, heredoc or here-string, a file scp or rsync copied there and run) and checks it with ~ as the remote home against ~/.ssh/id_*, config and authorized_keys; hook._segments ends a # comment at its line, so commands after a #! line or a note are read; tests; guide.md
- tests: two flaky runtime tests wait on the real condition, not wall time
