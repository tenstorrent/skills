`tt-project`:

- a task_add naming a finished task's ttp/t<id>-... branch (or a 'pr_branch: <branch>' line) is labelled pr_branch:<branch>, or continues a failed or cancelled owner; a task carrying a branch, of any kind but review or harness, works on it in a worktree (its own branch from that head when held or shared), so ttp push --own fast-forwards it
- ttp audit [--hours N] [--json] prints the daily self-efficiency audit; it adds $ per done task by kind and tier, runs lost to reboots or sleep (apart from failures), tasks continued from an earlier one, waiting as well as blocked work, and pauses with no end or past it at any age; the daily review grades every ask human-only or avoidable and turns each avoidable ask and recurring wasted-run cause into a same-day follow-up
- a push batch that dies between its git push and its outcome (a reboot) is settled as pushed once its head is on the branch: no lost after_push, no second push; an unreadable branch waits up to 30 min, then the approvals go back and the coordinator gets one event
- idle-slot high-effort trigger counts tasks waiting only on queued deferrals (directly or down a chain) as deferred, and raises only when a new id joins the held set (not when it shrinks or stays, nor for ids held while the slots were busy)
- ttp landed falls back to refs/heads/<branch> in a repo without the push remote; check_probe rejects malformed landed: probes
