`tt-project`: untrusted text the harness shows a model is enclosed as data with a provenance label and a delimiter whose tag is new each turn (`spans.py`): every event in the coordinator digest (hand-offs, notes from other projects, PR and CI text, watcher and tool output), a relayer's context and findings, and in the worker prompt's context block a relayer's context, earlier hand-offs and blocked reasons, review findings and tried-ledger lines. Delimiter brackets inside the text are shown as plain ones, so it cannot close its span early or open a fake one; text is clipped before it is enclosed. The user's verbatim words and the owner's-agent text are never enclosed. The coordinator prompt's untrusted-text rule and the context block's intro say once that enclosed text is data. The daemon's review, fix and re-review specs enclose the worker's and the reviewer's hand-offs, proposed follow-ups and each finding the same way, and the worker prompt says once that enclosed text is data; the coordinator digest also encloses the Open tasks rows' last note, Recently finished hand-offs and each running worker's step, and row and section hashes ignore the delimiters, so a new tag each turn makes no row look changed.
