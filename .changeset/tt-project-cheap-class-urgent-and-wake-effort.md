`tt-project`: an `urgent:` line (or priority 1) no longer puts a cheap-class run on Opus: wake decisions, screening, worker wakes, status reports, rebases, small reviews and light runs of an urgent task take their class's route (a tt model, else Haiku or Sonnet at low effort) and the task keeps its place at the front of the queue; the coordinator and hard work still run on Opus, and a failed run still retries a tier up. A worker wake of a code task no longer runs at the conclusion floor's effort (high): it starts at its class's effort, while the task's first run and its independent review keep the floor, as do questions, chat answers and status reports. A task labelled `untrusted_input` is never routed to the chat provider.
