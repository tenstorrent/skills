`tt-project`:

- prguard runs delivery.pr_body_check on PR bodies written through gh api (REST pulls POST/PATCH, GraphQL createPullRequest/updatePullRequest); the gh api PR body check treats /graphql as GraphQL
- a run in the project root that newly dirties tracked paths there is sent back once to commit or revert them before its done counts; the worker line on root edits sits in the non-PR block (code and review run in worktrees), keeping the code prompt under its cap
- a chat run with no saved key, or a key saved for another URL, goes to the provider's auth gate (logged-out pause) instead of a launch failure; check_pin verifies a chat model pin (the chat provider reports the model and effort its run is built with); tests that chat model ids are kept as pinned, dropped on failover to the core provider and kept by a required pin; the pre-grant re-ask lock test starts the hold only after the waiter's first take failed (a first-try take reuses its fresh answer by design)
