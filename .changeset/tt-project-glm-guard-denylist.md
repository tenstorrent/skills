`tt-project`: the GLM guards (the production GLM guard and the device plan guard) now refuse only a short denylist of harmful kinds measured on real runs: writes or deletes outside the run's worktree, run folder and scratch folder (and writes on another host outside a device plan's steps), pushes and landing before review, outward posts, resets, power cycles and flashes outside the approved routes, machine-ledger writes, and service state changes (`systemctl` start, stop, restart, enable, disable or mask and `service <name>` start, stop or restart, matched on the command's raw text, so heredoc bodies and ssh commands are covered; only a whole step of the device plan may). Protected paths, held Slurm nodes and recorded undos stay with the hook's other guards. Everything else runs, with the device plan and the post-run audit as the backstop. `ttp remove` is refused, and ssh options that run a local program are refused. A script file run by its path (`bash s.sh`, `ssh box bash < s.sh`) and a `$(...)` in a heredoc body a program other than a shell reads are not read by the guards; the guide documents this gap. The guards drop their heredoc, inline-code and ipmitool sub-parsers.
