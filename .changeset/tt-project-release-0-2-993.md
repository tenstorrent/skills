tt-project 0.2.993: a worker or coordinator never re-applies a pause the user lifted. A worker had paused a project to hand its fleet back; the user resumed it to put it back to work; minutes later another worker paused it again because a watcher saw the other owner's daemon process running, though that owner's CLI had been logged out for a day. Now a pause from a run (`ttp pause`, `ttp pause --resource`, `ttp drain`) of a project or resource whose latest resume was the user's is refused and changes nothing, unless `--user-msg <id>` cites a user message newer than that resume. `ttp resume` prints whose pause it ended, why and since when, and says so when it was not the user's. New `ttp alive <name>` answers hand-back and takeover checks: live only after a successful model run in the last 6 h (`--within`) with no provider logged out and the project not paused; a running daemon alone is no proof. New tests pin that a user, worker or coordinator pause, with its owner, reason and end, and a resource pause survive `ttp upgrade` with a pending template merge, the host-side takeover, an old-state migration and the daemon's automatic upgrade.
