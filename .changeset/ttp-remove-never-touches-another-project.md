`ttp remove`, `ttp remove --delete-files` and `ttp stop` act only on the project whose own folder is the one named: never a parent project found by walking up from the current folder, never a folder whose harness/project.json carries another project's name, and never when the service, registry row or running daemon belongs to another project. `--delete-files` refuses a folder that holds another registered project. `ttp adopt` refuses to take over another project's name. `ttp new --dir` refuses a folder inside another project and names the scratch place, ~/.tt-project/scratch/<name>, instead.

`ttp remove` always drops the removed project's registry row, also when its daemon or unit is already gone or a step fails part-way. A deploy (`ttp deployed --after-push`, or `--skip-removed`) leaves out, and names once, a project no longer registered or whose folder holds no project database, instead of failing on it. A project's systemd unit that finds the project's daemon running outside it (started from a shell or an ssh session) waits for it and takes over, instead of restarting every 10 seconds; the next service restart moves the daemon into its unit, and only that daemon is signalled. A worker's hand-off that claims no side effects is checked against the run's own records: another project's registry row removed, daemon stopped or unit stopped, a git checkout or reset in another project's folder, and writes outside its folders. A false claim is marked in the hand-off and raised to the coordinator; an effect on another project is raised even without a claim.
