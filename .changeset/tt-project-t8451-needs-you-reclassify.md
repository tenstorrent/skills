`tt-project`: an alert asks the user only for what they can and will do. A gh login on the host, the optional ranking key, a chat endpoint's key, a pause the user set and a pause a hand-back or move set are low status lines, never "needs you"; a schedule failing only for gh's login shows a held status line naming `delivery.gh_route`, and a task held on a gh login shows "held for the workstation gh queue" (or "no gh route"). A model-free sweep at daemon start and hourly closes open "needs you" items these rules would not raise, acknowledged to the feed as `reclassified: <rule>`, without re-raising the unchanged condition. With `delivery.gh_route` unset and the host's gh logged out, gh calls go to the workstation queue; `none` and an ssh alias are unchanged.

`tt-project`: a gh logout no longer clears for a minute and re-raises (user msg #2688): only a real login here or the project's own ssh `delivery.gh_route` answering clears it. The host-wide route record now names the route that answered, so the workstation queue or another project's route answering, or a routed call failing for want of a login there, no longer counts as gh working again. The gh no-login condition never reaches chat; it stays a web-app and status line across clears, restarts and upgrades.
