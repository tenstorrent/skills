`tt-project`: a coordinator action whose meaning is clear is applied as meant instead of refused and resent. `actionforms.normalise` runs first in apply and in the in-turn dry run, so both accept the same forms; each rewrite leaves one "applied as: ... (was: ...)" note and is counted as `normalised` in `ttp stats`, apart from refusals. Forms covered: a sweep `still_blocked` with no next check (the item's own next wake, else the sweep period) or no re-checkable condition (taken from the task's own wait), `unblocked` on a still-deferred task, and a sweep key sent in another field; an obligation owner that finished (its one open successor), owner #0, a milestone named on an obligation with none (recorded as progress, never a receipt), and a run's record from a task that carries an owner's work on (it becomes an owner); a `cells:` line with one trailing remark; a coordinator-settable config key, applied the way `ttp config` applies it; a throughput mute with one matching open task as its owner; a reply naming its message by `order`, or the one task replying to that chat; and a user's-words line whose quote is in exactly one recent user message. What stays refused: the ask gate, receipts on partial work, user-only keys and spend caps, quotes only in relayer context, change orders owned by review or plan tasks, missed dues moved without a plan, a held reply, and anything with more than one reading. A fault in a form leaves that action as sent.
