`tt-project`: coordinators, workers, reviewers and checks now run unsandboxed by default on every host and provider. They get no bwrap, no network or PID namespace, no Claude Bash sandbox and no no_new_privs, so `sudo` under `ttp lock` and in detached jobs works. Codex workers run in `danger-full-access` instead of `workspace-write`. Codex coordinator turns no longer pass `-s read-only`, and that includes the coordinator session. Safety still comes from the project's own gates: locks, device holds, pauses, spend caps, required checks, review before push and Restrictions. The daemon applies coordinator output only through its action gates. A project can opt back in. `providers.<name>.write_fence: true` turns on the worker write fence and, for Codex, the coordinator's read-only sandbox. `sandbox.checks: true` turns on the check process sandbox. A config without these keys runs unsandboxed. Each run records its sandbox in run.json (`"sandbox"`, `"none"` when unsandboxed) and on its daemon log start line (`sandbox=none`). A new model-free detector snapshots the project's harness folder and repo checkout before and after each coordinator turn. It reads `git status --porcelain` for a git work tree and top-level mtimes for any other folder, and logs a warning when the turn changed files. It makes no model call and raises no alert. Hiding device nodes from runs that hold no device (`TTP_NO_DEVICE`) is unchanged.
