`tt-project`:

- the runner never starts an agent whose STOP came first, ends it when the run dir is deleted or the runner dies (PR_SET_PDEATHSIG on Linux, a watchdog elsewhere); tt-project tests: stand-ins for every agent CLI first on PATH; a test that resolves or starts a real one fails; a killed runner ends its agent's whole process group on Linux too (the watchdog runs everywhere, PDEATHSIG stays as an extra); the reaper ends the tools of an agent that already exited when they carry the run's dir
- worktree.kinds gives other task kinds (say work) a worktree of their own; a run that leaves the project root's checkout on another branch or with new uncommitted tracked changes raises a low alert naming the task, which clears once the checkout is back; a run that moves the project root back to its base branch, or to where an open root-checkout alert wants it, is not alerted; one root-checkout alert per change, blaming the runs that worked in the project root (others only 'also running'), and no second dirty-checkout note for its paths; work tasks in a worktree of their own get the local-only, backup, integrity and continues-branch handling of code tasks; tt-project tests: the daily-review debounce test checks the skip waits for the next regular slot, so it no longer fails in the hour before that slot
