tt-project: chat model failover, scoring and demotion, landed together.

- Served-model watch: the chat endpoint's /models list is polled once per machine and endpoint for every project on it, every 30 seconds while any project routes work to chat, else every 5 minutes (account keys `providers.chat.served_every_s` and `providers.chat.served_idle_s`). One daemon holds the poll lease; another takes over 90 seconds after it stops. The shared list under `~/.tt-project/served/` records when each model was first and last listed, and an events file records each model that appears or goes away. A list older than 3 poll intervals counts as unknown, so no swap rests on an old list. The key and URL are never written.
- Mid-run swap: a chat run whose model goes away mid-run (a refusal, or 3 errors in a row while the /models list leaves it out) moves to the highest-ranked served model in the same session. The run note keeps each swap (`model_rank.mid_run`) with one low alert; a required pin never swaps. Babysit asks the next ranked served model once before it falls back.
- Scoreboard per class: `ttp model-bench scores [--json]` ranks models per task class (babysit, light, standard, review) from bench scores (else the Artificial Analysis index as a prior) blended with live first-try results by sample count, with median wall time and tokens/s. It publishes `providers.chat.class_ranking` under `providers.chat.class_prefs` (smart, fast or auto) and keeps `providers.chat.model_ranking` equal to the standard class.
- Demotion per class: the daemon's hourly model check (model-free) compares, per class over the last 7 days, each chat model with the next eligible one. With 8 samples on each side, a bad rate more than 15 points worse, or in a fast class a median wall time over twice the peer's, demotes it for that class. A model whose malformed or no-hand-off share passes 20%, or whose bench score is under half the best, is parked. Each action is one low alert and one coordinator digest line; only a newer passing bench score ends a demotion. `ttp model demote|promote|park|unpark <model> [--class c]` sets these by hand with the setter recorded; the user's record stands over a coordinator's. Settings: `providers.chat.demote`.
- Bench owner: one project per machine owns the daily chat model bench. The first eligible project by name (live daemon, chat endpoint, not paused, no `model_bench.opt_out`) keeps a model-free command schedule that runs `ttp model-bench run --detach` at `model_bench.bench_at` (default 02:00 home time). Every daemon checks the lease hourly without a model call: after `poke_after_h` (48 h) with no result it pokes the owner once; after `take_over_after_h` (72 h), or when the owner is paused, opted out or down, the next project by name takes over under a lock, with one low alert naming both.
