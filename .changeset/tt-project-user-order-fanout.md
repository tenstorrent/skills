`tt-project`: a user order now reaches every running worker it affects mid-run, not only workers on a resource the order names. When the coordinator records an order (`obligation` with `order`), the daemon tells, once per run through its `steer.md`, the running tasks that own or are attached to it, answer its chat, or whose spec, unlanded branch or resources name a path or resource it names. The update quotes the user's words under "user's words (verbatim)" and lists the older spec steps it replaces when the coordinator gives them (`supersedes`). A Goals change reaches the running tasks it touches; a Restrictions change still reaches every running run, now with the user's words. Each fan-out, and an order that matched no running task, is logged as a `user_order_fanout` event and a note naming the tasks told. Orders on a named resource keep their resource hold and update, and a run already told of an order is not told again.
