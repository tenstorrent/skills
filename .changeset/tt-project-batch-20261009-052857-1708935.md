`tt-project`:

- a passed review's event names the tasks waiting on it; the coordinator hands them its result with a spec-only task_update, never a relay-only worker run
- task_add/task_update start_when 'now' (any case) clears the probe instead of storing it as a command; start_after takes '' and any-case 'now'
- new/setup/upgrade give the harness repo a local git identity when its own config has none, so harness commits work
- a hand-off event's summary leaves room for the daemon's review and fix lines under the digest cap
- template upgrades settle a local edit upstream now makes too, and keep a project's prompt blocks in upstream's text; a template upgrade no longer takes upstream's side when it reworded a line the project removed, or for a '#' line inside a Python string
- devq's opt-in host job guard refuses jobs without process-group isolation, downloads without a disk guard, cache paths on network mounts, submits over a disk cap and unreadable declared inputs; the run-dir deletion test retries its delete while the runner still writes its launch files
- push queue records each task's landed commit; start_when landed:#id; ancestor probes match rebased commits; tests and prompt docs for landed:#id and rebased ancestor probes; landed:#id never passes for a task that has not landed anything (branch fallback only for a done task with commits of its own)
