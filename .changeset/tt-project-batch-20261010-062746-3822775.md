`tt-project`:

- a code task continuing a review (continues:<review>) starts from the head of what that review reviewed (its reviewed branch, or a fix branch built on it), not the base, so its head contains the reviewed branch and its worker need not rebase by hand
- ttp push detects a branch's real base; a branch based outside the push flow is never rebased onto the push target: pushed to its own branch as a fast-forward once on the remote, else refused with the rebase --onto to use; a run's STOP file is written whole by rename, so a supervisor polling mid-write never records `ttp stop --kill` as a cancel; a run's STOP file is written with durable_write (whole by rename, synced)
- setting hold: while an open ask names delivery.allow_protected_push_branch (off), the daemon holds tasks that land with ttp push (blocked on the ask, attempts untouched) and releases them together once it is on or no open ask names it; the digest shows each hold as one line; setting hold review fixes: hold only while ttp push refuses the push branch because the setting is off (main/master, or the remote's default from local git), ask lookup on the indexed outbox; landing specs match only ttp push instructions or 'land ... on' the push branch, never mentions, no_push specs, --own anywhere in the flags or a command negated earlier in its sentence; setting hold tests: rename the remote helper so it no longer shadows _with_origin
