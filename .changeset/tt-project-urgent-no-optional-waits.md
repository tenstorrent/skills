Urgent work (priority 1 or an `urgent:` spec line) skips two more waits that are not safety rules. An urgent code task with a `premise:` line now checks the premise as its own first step instead of waiting for a separate light question task (a queued, unstarted question is cancelled). In the `ttp lock` waiter and checks queues, an urgent waiter now goes ahead of routine landings (urgent landings first), while waiters past the one-hour age bound still lead and no running holder is stopped. The coordinator and plan prompts split an urgent goal into tasks that start at once, chained only where one needs another's new file or symbol.
