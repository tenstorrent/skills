`tt-project`: a `ttp lock` waiter running inside a landing's checks (`ttp push` to the push branch, the push queue's batch checks, `ttp land`), from any project, goes ahead of non-landing waiters on a shared lock, in arrival order within each class. Only the harness marks a landing: the process running each such check (the push queue's batch process for its checks, reruns and cap probes; `ttp push` and `ttp land` for theirs) holds a landing mark and `ttp lock` counts it only when an ancestor holds it, so a forged marker gets normal ordering. A waiter of an hour or more is never passed by later landings, and no holder is preempted. The `ttp lock` wait line says whether the waiter and each holder are landings, and names each holder's project from its record's own project root, never its project field; it only reports, and never stops or requeues another project's run. `ttp land`'s checks also take their local branch's priority slot on the host checks queue, as push batches and `ttp push` to the push branch already did, so a landing no longer waits behind earlier task checks of other projects.
