`tt-project`: refusal audit follow-ups. The guard test on the coordinator's batch loop now reads every list the loop keeps across a batch from the code, not from a hand list, so no new one can be rebound into the "'tuple' object has no attribute 'append'" crash behind the audit's internal-error refusals. Every refused hand-off wait (no shell command, the checks.running marker, the charter, an unfiled upstream note, an unset run variable) goes through one `waitheal.refuse_wait` helper, with unchanged texts. The charter check reads `machine_ledger.configured_names` directly. A dropped charter wait asks for the charter_update to be resent fixed only when the turn's charter_update was refused. The held-machine inventory lists a project's schedules even when its open tasks cannot be read, and reports the failed read, or a project database that cannot be opened, as an unverified item; such an item stays in the status line and is never sent to its project as a note to stop work on the held machine. A refused hand-off wait's event text keeps its 1500-character cap.
