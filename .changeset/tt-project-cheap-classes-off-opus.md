`tt-project`: run classes that do not need Opus go to the tt models (wake decisions, screening, worker wakes, status and report work, rebases and conflict fixes, small reviews, light tasks); the coordinator and hard work stay on Opus; `route.classes` overrides one; `ttp stats --by-class [--since 1h] [--json]` counts runs per class per model. When no tt model serves a cheap class (none configured, or its endpoint fails the auth probe or is cooling), a standard-tier run of that class on Claude takes a cheap Claude model at low effort instead of Opus: Haiku for wake decisions and screening, Sonnet for worker wakes, status reports, rebases and small reviews (`route.core_cheap`: false for none, or per class false or `{"model", "effort"}`). It goes back to the tt model by itself once the endpoint answers with a working key, with no config edit. Task pins, urgent, needs-deep and untrusted-input tasks keep their tier's model. The run_class_quiet alarm counts these cheap runs as served: it fires only when a cheap class's eligible runs fell to Opus. "tt models unavailable" is told once per outage as a low alert, and told again only after a tt model has served in between. The chat (GLM) watcher's answer now decides wake-gate wakes. This release also includes the untrusted-input guard follow-up: `curl -sX POST` counts as a write, and tokenizer files are not credentials.
