# Readiness probes

A `start_when` or `retry_when` that waits for a device or box checks it live and read-only (the broker's status, `tt-box-clean-probe`), never a bare marker file such as `test -f state/ready/<box>.READY`: the file outlives the box going down, so the task starts against a dead box.
A probe on a status listing tests its job rows, never a section header word the listing always prints: `tt-device-mcp status | grep -q RUNNING` matches with nothing running, because the RUNNING header shows with no job under it, so a `start_when` or `end_when` built that way never waits. Test a row under the section (a job id, owner or command), or the job `status` fields of the broker's JSON job list (`tt-box-clean-probe` reads it). `task_add`/`task_update`, `ttp task add --start-when`, `ttp task set-when` and a waiting task's `retry_when` flag (never refuse) a grep of the broker status listing whose whole pattern is such a header word (runtime `waitheal.header_grep`); a Slurm state probe (`squeue -h -j <id> -o %T | grep -q RUNNING`) is correct and not flagged.
A wait for a broker hold to end checks with `ttp broker-released` (runtime `brokerhold.py`), which counts /health `held` false with a healthy fsm, a `hold released` log line and a `device_released` event alike: a check that only looks for one of them misses a release the broker reported another way.
A marker that is used is removed by whatever writes it when the resource is paused, shows trouble or fails its probe.
`task_add`/`task_update`, `ttp task add --start-when` and `ttp task set-when` flag (never refuse) a probe that only tests a readiness marker.
A hold only the user's word lifts is written `test -e state/user-<x> || exit 1` (the marker pattern is `coordinator.user_pause_marker`). An `||` of that marker with other plain marker-file tests (`test -e state/user-<x> || test -e state/<other> || exit 1`) is a user hold too.
A user hold raises no probe stall, no wait_stale and no blocker-sweep outcome (runtime `userpause.is_probe`, the one classifier all three use). Anything else, such as a marker AND-ed or OR-ed with ssh, a command or a pipe, is a live probe that the stall check watches.
A probe stall open over `coordinator.probe_stall_dispose_h` (default 1 h) is settled model-free by the blocker sweep: when every task the wait names is done (and on the push branch, for `landed:#<id>`), the probe is re-run and, if it still says not yet, the task is released once with a note to check its probe; a probe that greps a literal sha is flagged (wait with `landed:#<id>` or `ttp landed <sha>`); a user-gated one is left alone (runtime `sweep.dispose_probe_stalls`).
A probe stall wakes the coordinator once, then only every `rewake_h`: its count grows with time alone, so it never escalates. A `start_when` that keeps saying not yet (exit 1, 75 or 255) is a healthy wait: its gate line never warns, and the daemon probes it every 3 min at first, then less often, at most every 10 min (a `landed:#<id>`, `ttp landed`, job-result, `ttp ci`, ack-wait or date probe keeps 3 min, and `landed:#<id>` re-runs within about 30 s of a recorded push). Past `waiting.start_gate_warn_s` the gate warns only when stuck: another exit code, or a `landed:#<id>` producer that failed, was abandoned, is already pushed, or that nothing open can land (runtime `startgate.stuck`, `startgate.every`).
A probe prints one short line naming what it waits on (`build dir held by job 42`), its last line: for any probe but `ttp lock --probe` (whose note names each lock's live holders) the daemon's wait note shows that line and when it was read, ahead of the worker's `waiting_for`, labelled as the worker's note from its time; a probe that prints nothing leaves that note marked as possibly stale (runtime `waitheal.live_note`).
Probes run in the project root: a relative path is relative to it. Only 0 (passed), 1, 75 (not yet) and ssh's own 255 are valid exits; any other (grep's 2 on a missing file, 126, 127) is a broken probe, raised once as an event (`deferral_probe_broken` for a start_when, `hold_probe_broken` for a `waits_on when:`) or a wake for a retry_when. Never turn it into 1 with `|| exit 1`: the daemon then sees "not yet" forever. `task_add`/`task_update`, `ttp task add --start-when` and `ttp task set-when` flag (never refuse) a probe that reads (grep, cat, jq, ...) a relative path with a folder and a file extension that does not exist under the project root (runtime `coordinator.missing_file_probe`).
A probe that tests something and then always exits 0 (`test -e <path> || true`, `check; exit 0`) is refused at every wait: a `start_when` or `retry_when`, a pause's `end_when`, an `observation_mute` `end_when` and a memory or charter `until_probe` (a bare `true` stays a deliberate "now" for a task). Make it a real test that ends with `|| exit 1`. One stored before that is never run: it is reported once as broken and never starts a task, wakes it before its retry time (it then wakes as a broken probe), lifts a pause or ends a mute or entry; only its time does.
Exit 255 is ssh's own only (the host does not answer): quote the remote command as one string (`ssh <box> 'test -e <path>' || exit 1`) and let a failing remote command exit 1 or another code, never `|| exit 255`.
Before a probe's 255 counts as unreachable (and toward the network outage alert), the daemon checks each host it names with `ssh -o BatchMode=yes -o ConnectTimeout=10 <alias> true`; one that names no host, or whose host answers, is a broken probe for its task (a start_when's comes to the coordinator as an event, a retry_when's wakes its task).
Write a pause's `end_when` the same way: an `end_when` or `until_probe` 255 gets the same check (in the background), and one whose host answers is reported as a broken probe.
