# Charter guard

The coordinator's `charter_update` (runtime `coordinator.py`, `_reject_contradicting_append`) refuses added text that a standing Restrictions item would contradict, quoting the item and naming the forms that pass: a quoted resend, `both_hold` plus a companion edit for an exception, or `both_hold` (or the text saying it loosens no restriction) when both hold.
Each refused item is quoted by its one conflicting sentence, with its section and a one-line reason (what it bans that the text may permit, or what both rule on); several are listed each.
A scoped exception is new Restrictions `text` sent with `excepts`, the clause of a standing ban it narrows (`_scoped_exception`). It passes when `source` is the user's verbatim words (a checked `{msg, quote}`, or the owner's agent's words with agent mode on), the text may permit what the clause bans and names a scope the clause does not (a backticked name, a word with a digit, underscore, slash, file suffix or one-letter hyphen part such as host-a, or an end), with no general word (any, all, every, no longer, ...), and no other ban it may lift names a thing in that scope. Bans that name none of its scope hold alongside. It is stored as its own item, `Exception to "<clause>" (<section>), which holds everywhere except inside this scope, where this item wins: <text>`; the clause's item is never edited, and the lint no longer pairs the two.
A companion edit keeps the quoted item word for word and only adds a clause naming, by id, an exception that stands in a temporary or dated Restrictions section, with no object or action of its own, on the sentence that exception is about.
The user's yes to that exception covers it in a later turn and it is checked against its own item only.
Removing or really loosening an item still needs the user's word or `over`. In a user turn, removing or replacing a cited item (`(user msg #N)`, `(origin: ...)`) applies only with `source` `{msg, quote}`: the quote must be in that turn's verbatim user words (or, with `coordinator.agent_orders_as_user` on, the owner's agent's order words), never the relayer's context (`restriction_source.turn_quote`).
Outside a user turn, a `charter_update` whose `source` `{msg, quote}` quotes a logged user message verbatim (its own words, or with `coordinator.agent_orders_as_user` on the owner's agent's order words; never relayer context, findings or notes) counts as the user's word, checked by `restriction_source.check` (`coordinator._cited_word`); a mismatched quote or one naming no logged user message is refused as before. A Restrictions change resting on such a cite that the turn cannot apply (a cited item removed or replaced) is queued: the yes is recorded for that exact change (within `coordinator.charter_approval_days`) and a `charter_retry` event raises it next turn, where the same resend applies.
The refusal says a user's loosening goes in as written (a quoted resend on their word, no `over` and no end they did not give), and names the temporary-exception route only when the user's own words make it temporary.
After such a loosening or removal (`quote`, or `replaces` of a Restrictions section, judged item by item), or an `over` retirement, a `restriction_tools` event (runtime `restriction_audit.py`) names the tool files still carrying the old item's terms; it never edits them.
A refusal that names such a fix raises an immediate `charter_retry` event, at most two per change.
A Restrictions change refused for its source (none, or one the gate could not check) whose `source` names a user message, or whose `text` cites one ("(user msg #N)"), comes back with a filled resend first (`chartertemplate.py`): the same section, `quote` and `replaces`, `source` `{msg, quote}` read from that message's own words in the chat log, and `text` without cites; the reason follows in one line, and its `charter_retry` event carries the same resend. The gate checks the resend like any other. Any other refusal (an ambiguous `replaces`, a missing approval, a held class, a removal needing this turn's words) keeps its full error, as does a change with no readable cited message (unknown, not the user's, no verbatim words). The chat that message came from gets one alert per item and refusal cause, cleared with one low line once the item lands.
A Restrictions item binds only when it cites its source (runtime `restriction_source.py`): a user message id ("(user msg #N)", "user messages #N, #M"), "(origin: Brief)" or "(origin: harness gate)"; a nested bullet or continuation line counts as part of its item, a sub-heading is an item of its own.
New or changed Restrictions text needs `source`: `{msg, quote}` with the quote in the user's own words of that message (never the relayer's context, unless `coordinator.agent_orders_as_user` is on: then the owner's own agent's context and findings count), `{origin: brief, quote}` with the quote in the Brief, or `{origin: gate}`, sent as that object's JSON text (the action schema types `source` as a string; an object works too); each refusal names the check that failed (missing, not JSON, origin, message, quote); the cite is added to each item that has none, and a cite in the text that the source does not name is refused. A charter change the user said yes to is cited with that message.
With `coordinator.agent_orders_as_user` on, a Restrictions change resting only on the owner's agent's words (`source` `{origin: relayer, msg, quote}`, a findings-only turn, or the agent's yes to an ask) is applied, cited "(relayer-ordered, msg #N)", and logged as a `relayer_ordered` event, a low feed line and a daily-review line, each with the old text. Rewording or removing an item about a step `relay.HELD` names (affecting other people, speaking as the owner, a credential, money or a spend cap), or adding text that lifts one, is refused by class: it needs the owner's own words. The refusal quotes the words that matched, where (the quoted item, the new text, a replaced line) and the class. A `quote` edit is read by the clauses it changes (`_changed_clauses`): both sides are split at , ; : a sentence's '.', and before an ' and ' that starts a held step; a clause both sides keep is not read; every class runs on each changed clause, with no scope or word exemption; an added or dropped clause also reads its neighbours and every clause of its sentence, on both sides (fails closed). A record cite such as "user message #12" is no message. Known gaps: a clause reworded inside a kept sentence ("no exceptions" to "exceptions when CI is green") and a word in one clause that governs another are read only where they stand. A held word its own clause negates ("no other tenant", "not shared with others", "without affecting other teams", `relay._NEGATED`) is no held step, nor are "postpone" or "tokens per second"; a negation that does not govern the step ("never ask before force-pushing", "no need to delete") still matches. With agent mode on, a quote-check failure names the fix (resend with `source` origin relayer), and `orderedask.refusal` refuses an ask_user (blocking restriction, or irreversible worded as a permission question) for what a logged inbound message of the last 7 days ordered (its id cited, or a phrase of its verbatim words or labelled agent context outside the charter repeated) with that fix; held-class, funds, spend, review, merge, access and human asks, and one whose `not_covered` says what differs, still go out. Agent mode off: unchanged.
An item with no cite is advisory: prompts list it apart from the binding block (workers never get it as binding), the coordinator removes it without the user's word or `over` (a whole section only when every item in it is unsourced), and an ask about it alone is refused with the drop instruction.
Charters written before this rule keep their uncited items as advisory until the coordinator resends them with `source`.
Raise `CHARTER_GUARD_VERSION` and its pin when the guard changes.
