/goal Use $agentic-serving and $tt-device-usage for HF_MODEL after the benchmark stage in the current tt-metal checkout.

Subagents are authorized when a selected skill requests or recommends them.

This goal runs agentic evals on the served autoport and tunes its serving configuration for them, following the goal-12 section of $agentic-serving. Read bringup/agentic_evals/inputs.json if it exists; otherwise use that skill's defaults. Use only the hardware the inputs grant, and keep it busy.

Goal completion requirements:
- Eval names and versions, agent and request time limits and the output cap are set so the model can finish, never below the release values, which the stage finds itself; full evals run on the largest validated batch unless a recorded reason says otherwise.
- Before any scored sample, doc/agentic_evals/survey.json answers every check and calculation in the skill's survey, prices each shortfall carried from earlier stages in suite hours, and doc/agentic_evals/preflight.json records the release spec it read and shows the registry, disk, release route and an isolated smoke passing.
- doc/agentic_evals/efforts.json ranks every problem the survey found by predicted suite hours saved per device hour, with guesses marked and a reason recorded for any departure from that order, and re-ranks after each effort. Each effort has a goal and confirmation set by the coordinator, a plan by its sub-agent, a device-hour time box, and records the change and the problem status with the confirmed result. Efforts run in parallel within the effort budget and share the local device through one queue. Exact changes are accepted on a paired exactness check plus their confirmation; others need a scored pair against the current best. Kept changes are re-checked together.
- doc/agentic_evals/estimate.json records per eval a go/stop decision and reason, first from the survey and updated after each effort from the calculations, not from full suites. Full suites run only on go and record actual hours next to the prediction. A measured stop is a valid outcome.
- doc/agentic_evals/serving_config.json records the measured serving values a release spec needs, and doc/agentic_serving.json `workload` is updated with measured values.
- doc/agentic_evals/REPORT.md leads with hours per suite and scores against references, then each effort's predictions against its results, the chosen configuration and remaining limits. Scores are reported, not gated.
- Only owned processes and containers are stopped. Commit stage-owned changes to the execution checkout locally and log SHAs; never push that checkout or add a remote to it.

Unmet requirements and failed gates: work. Use $autofix for execution or integration failures. Stop only after `$autofix` fails or the stage budget ends, preserving partial results and the reason.
