/goal Use $agentic-serving and $tt-device-usage for HF_MODEL after the benchmark stage in the current tt-metal checkout.

Subagents are authorized when a selected skill requests or recommends them.

This goal shows the served model scores like its reference on agentic evals, at a speed the measured serving rates explain. Read bringup/agentic_evals/inputs.json for the mode (quick, agentic or extended; each includes the one before), suites, list sizes, references and limits; $agentic-serving gives the defaults. Run on this machine.

Goal completion requirements:
- Phase 1: GPQA Diamond, 10 tasks (or inputs phase1), scored on main's harness. The score is within the ok_band of its reference, and the measured wall time is within explain_tolerance of the time explained by tokens ÷ the doc/benchmark/serving_rates.json rates plus measured time outside the server.
- Phase 2 (agentic and extended modes): SWE-bench Verified, 10 tasks from the skill's fixed diverse list (or inputs phase2), passing the same rule.
- Every run uses the skill's server size: pool from measured free DRAM, then agents from the KV cache and task sandboxes, then the smallest validated batch that holds them; the fastest projected finish breaks ties.
- Every failed or timed-out task has a per-task analysis: cause, evidence, and the rerun result if rerun. Failing tasks are rerun individually; a rerun changes the score only when the first failure was infrastructure. A task that fetched its own solution is a failure and stays in the denominator. Network use a task declares is allowed. No list is voided.
- Extended mode, after both phases pass: full-suite estimates from the phase runs, speed work by the skill's measurement method, then per suite in extended_suites the largest list whose projected run fits run_timeout_hours with margin, scored by the same rules.
- doc/agentic_evals/results.json records each run's list, config, score with 95% interval, reference and its source, predicted, explained and measured hours, collection, failures, and each phase's pass. learned.json records the best config per suite for the next model.

Limits:
- stage_budget_hours: quick 12 (phase 1 only; target run under 5 h), agentic 24, extended +24. run_timeout_hours (12) and the Codex usage budget from inputs.json; runs are admitted on measured times.
- Agent and request limits and output cap from the harness reference, never raised. Main's harness and route, unchanged. Stage 11's rates are read, not re-measured.

Priority: phase 1, then phase 2, then extended. A failing phase is analysed per task before anything grows.

- doc/agentic_evals/REPORT.md leads with each phase passed or not, scores with intervals against references, hours predicted against measured, and the failure analysis.
- $stage-review returns `clean-pass`; findings fixed/rereviewed. Local commit stage-owned changes; never push; log SHAs.

Unmet requirements, review findings, failed gates: work. A failing phase is unmet work, not a stop, unless inputs.json decisions records the operator accepting it; ask by marking the goal blocked with the question. Stop only after `$autofix` fails or that decision exists.
