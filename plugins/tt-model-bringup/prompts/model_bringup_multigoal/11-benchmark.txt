/goal Use $benchmark-model, $agentic-serving, and $tt-device-usage for HF_MODEL after optimized-vLLM in the current tt-metal checkout.

Subagents are authorized when a selected skill requests or recommends them.

This goal measures the serving rates the agentic-evals stage reads. Use the working stage-10 vLLM server, or, when bringup/agentic_evals/inputs.json sets entry: existing, the server's tt-inference-server model spec. Benchmarks only; evals run in stage 12.

Completion requirements:
- On the route stage 12 will use, with the sampling settings its harness sends (temperature, top-k/top-p, seed; they can move sampling between device and host), measure warmed vLLM performance for a batch × input-length grid: every batch in batch_sizes that stage 10 validated, each with max-num-seqs and request concurrency set to the batch and, above batch 1, also at concurrency 1, at input lengths 4096, typical_context_tokens, working_set_tokens, at least 28K and the longest context the evals reach (prompt plus output cap, at most max context) where the pool holds it, 128 output tokens. Also measure every benchmark row the release spec lists for this model (from its tt-inference-server spec, or the closest model's for a new model; record which).
- Every row completes, or is listed in missing_rows when the budget ends. Record the prefix-caching setting; precision, model, hardware and doc/context_contract.json are unchanged.
- Each row has a predicted rate written before it was measured; a row slower than its predicted range has a recorded cause.
- Each profile has full-phase host wall times with matching prefill FLOPs and decode DRAM bytes, collected without changing the serving path.
- A few long sampled generations through the served route, at the served model's own sampling defaults and about the output length the evals expect, are checked for anomalies; any anomaly is recorded for stage 12 (doc/benchmark/anomaly_check.json).
- Write doc/benchmark/serving_rates.json: the server config, validated_batches, the workload lengths used, and per batch, concurrency and input length prefill_tok_s, decode_tok_s_user, ttft_s and step_ms, with the predicted value beside each.
- doc/benchmark/run/REPORT.md leads with the grid and the release rows, then predictions against measurements and named gaps. identity.json proves the imported module (or model spec), revisions, precision, hardware, commits and launch configuration.

Limits: finish within benchmark_budget_hours from inputs.json (default 3). When it ends, list each unmeasured row in serving_rates.json missing_rows (batch, input_tokens, reason) and complete; stage 12 reads what exists. Main's benchmark client, unchanged.

- Run the evidence and context checks. $stage-review returns `clean-pass`; findings fixed/rereviewed. Local commit stage-owned changes; never push; log SHAs. Stop only owned processes and follow reservation ownership.

Unmet requirements, review findings, failed gates: work. Use $autofix for execution or integration failures. Stop only after `$autofix` fails.
